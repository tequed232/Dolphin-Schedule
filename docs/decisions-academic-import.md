# 学校教务导入方案与边界

当前源码已经接入 App 内手动识别、原生预览、确认替换、撤销和登录保留选择。首版仅适配广东财贸职业学院教务系统；定时刷新、待确认差异通知、更多学校与合并手动课程未实现，也不在 1.6.0 范围内。发布状态以 GitHub Releases 为准，实际登录与识别兼容性以当前学校页面和目标设备测试为准。

学校入口：[个人学期课表](https://jwxt.gdcmxy.edu.cn:1004/#/jwxt/js/student/personal/studentSchedule)。

## 方案选择

| 方案 | 适用方式 | 当前选择 |
|---|---|---|
| App 专用 WebView | 用户自行登录、选学期、点击识别，再回原生页核对 | 主流程；符合 App 内一键识别需求 |
| 外部浏览器与文件 | 用户在学校系统导出文件，再回 App 导入 | 页面或登录不兼容时的回退方式，取决于学校导出格式 |

系统浏览器与 App WebView 会话彼此独立，不能靠打开浏览器直接读取任意已登录页面。App 不接管密码或验证码，不使用代登录服务器、云账号、OCR 或外部 AI 识别。

## 用户流程

1. 从导入页打开教务浏览器。顶部提供返回、可编辑地址和刷新；仅接受已适配的 HTTPS 教务及统一认证地址。
2. 自行登录，进入个人学期课表，选择从第 1 周开始的完整学期范围，取消“大节次”后查询。
3. 按需勾选“记住登录 · 仅此设备”，点击“识别课表”。低频说明收在帮助中，没有电脑模式或方向切换按钮。
4. 回到原生预览，先核对开学日期；没有可靠日期时先设置日期再生成课程预览。
5. 展开需要核对的逐节作息和课程，检查新增/移除数量、地点、教师及周次，勾选确认后替换当前课表。
6. 需要时选择“撤销上次教务导入”，预览后恢复导入前课表。导入后的手动课程修改也会被替换，教材、背景和偏好保留。

确认前不写入。预览恢复或本地课表发生变化后必须重新核对；旧草稿不能直接覆盖最新课表。

## 读取与标准化

提取脚本按学校页面结构读取可见完整表格，区分隐藏打印副本、星期表头、时间轴、课程、教师、班级与地点。不以非空格子的顺序猜星期，不通过课名去掉合法的同名课程。

| 项目 | 当前规则 |
|---|---|
| 学期 | 识别所选学期和查询周范围，拒绝从中间周开始的局部课表 |
| 日期 | 同源学期接口返回有效日期且学期匹配时采用，否则要求用户确认 |
| 节次 | 每行必须有名称及起止时间，按完整时间轴确定数量，最多 24 节 |
| 中午时段 | 保留“中午1”等学校名称与实际数组位置；显示时只收起无课程占用的午休占位 |
| 周次 | 展开 `4;6-9;12-18`、单周、双周等表达，拒绝非法范围 |
| 连堂课程 | 仅在名称、教师、地点、星期及周次一致、原始节次确实相邻时合并 |
| 地点 | `--` 等缺失标记转为空，保留课程并提示补充 |
| 标识 | 完整内容相同尽量沿用现有课程 ID；新课程使用稳定内容标识并检查冲突 |
| 差异 | 比较课程内容、日期与逐节作息；课程内容变化显示为新增与移除 |

开学日期读取使用 `/api/baseInfo/semester/selectCurrentXnXq` 提供的 `semester` 与 `ksrq`。接口失败、超时、日期无效或与当前选择学期不符时，不把当前学期日期套给历史课表，也不根据学期标题推算日期。日期所在周的周一计为第 1 周。学校可能改版，该接口不能作为永久契约。

只接受可判断加载完成的个人学期课表。多份可见主体、缺失星期列、时间轴异常、课程字段不完整、超限或空课表会停止识别，保留原课表。提取结果上限 700,000 字节、2000 个课程块，普通节次和中午节次分别验证学校编号连续性。

## 登录与 WebView

浏览页仅允许 `https://jwxt.gdcmxy.edu.cn:1004` 与 `https://sso.gdcmxy.edu.cn`（默认 HTTPS 端口或 443）。编辑地址不会扩展允许范围；证书失败停止连接。学校页面没有 Dolphin 业务能力桥，结果通过私有文件与请求标识交给原生页校验。

会话使用 AndroidX WebKit 独立 Profile。勾选记住登录仅在本机保留站点会话，不主动读取或保存密码；清理只影响 `dolphin-academic-` 前缀配置，不删除默认 Profile 的旧课表库。取消保留时清理对应 Cookie 与站点存储，被 WebView 引擎占用的目录延迟到后续进程删除。

设备 WebView 不支持 `MULTI_PROFILE` 时明确提示更新，保留文件导入入口，不退回共享登录配置。“WebView 不可用”需要核对设备组件支持与初始化阶段；不能靠更换 Kotlin 语法或忽略证书验证解决。

## 数据与实现位置

| 路径（相对应用源码） | 作用 |
|---|---|
| `academic/AcademicActivity.kt` | 地址、登录、学校页面、提取与私有结果回传 |
| `academic/AcademicPolicy.kt` | HTTPS、主机、端口、课表路径与请求标识限制 |
| `academic/AcademicProfileCleanup.kt` | 教务会话清理与占用目录延后删除 |
| `assets/academic/extract.js` | 构建内置的学校页面读取脚本 |
| `domain/AcademicImporter.kt` | Kotlin 转换、校验、稳定 ID、差异及撤销 |
| `data/AcademicCodec.kt` / `AcademicDraftStore.kt` | 结果解码、私有草稿和编辑基线 |
| `ui/NativeImportScreen.kt` / `DolphinViewModel.kt` | 日期优先预览、确认、返回与事务接线 |

表中 Kotlin 路径相对 `app/src/main/java/com/dolphin/schedule/`，资源路径相对 `app/src/main/`。这是内部学校适配结构，不提供第三方插件注册、远程脚本加载或插件市场。

导入新课表和前后快照在同一 SQLite 事务保存。撤销仅保留最近一次，不能代替完整备份。草稿存在应用私有目录；Activity 状态保存标识，不塞入整份结果或图片。

## 后续设想与验收

定时刷新需先验证稳定的只读接口和会话复用。若以后实现，变化应先成为待确认候选，通知用户预览；登录失效、验证码、异常空表或解析失败不能自动覆盖。周期调度、频率设置和差异通知目前没有入口，不将这些设想写成已交付功能。

当前测试包括学校 URL 边界、合成页面提取的拒绝路径、Kotlin 复杂周次与特殊节次、动态作息、稳定 ID、预览保护和事务撤销。模拟结果不代替真实账号登录、验证码、学校网络与设备 Cookie 清理测试。验收时确认取消不写入、日期无法读取有明确路径、教务改版不覆盖原课表、教材和外观保留，且真实姓名、学号、Cookie、令牌与私人课表不进入源码或公开证据。

构建与测试入口见 [开发说明](development.md)，完整备份和迁移见 [数据说明](data-and-migration.md)。
