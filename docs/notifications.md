# 提醒、导航行程与系统实时更新

提醒、导航行程和通知栏小伙伴依赖 Android 宿主，GitHub Pages 不提供后台通知调度。进入“设置 → 实时通知”后，“Android 实时通知”是总开关，上课提醒、导航行程和通知栏小伙伴分别控制。行程显示时小伙伴隐藏，结束后按偏好恢复。

先按系统提示允许通知，再按需开启课前提醒、设置提前量。学校与地图偏好位于“设置 → 导航与学校”。普通课前提醒与用户主动开始的持续行程使用不同通知路径。

## 提醒与行程

课前提醒展示当前课程、教材和地点。点击“去教室”后撤下相应提醒并开始行程，地图由用户选定的外部应用打开。

行程通知使用课程名称、教材封面或品牌图，以及“去教室”和“我到了”操作。展开布局不重复展示完整地址，也不展示计时与数字阶段；完整地点位于地图操作中，折叠状态显示短楼栋标签。点击“我到了”直接结束行程，不拉起应用或补发行程到达通知。

同一课程的重复导航不重置当前行程的结束时间。每段行程有独立令牌，旧卡片的到达或超时回调不能撤下新行程。小伙伴只在无行程、相关开关开启时显示。

提醒根据当前课程、日期、时间和通知开关校验。同步相同待触发课次保留原提醒批次；旧 token、已删除或改期的课程、已关闭的提醒不会重新派发。

提醒使用系统允许的非精确闹钟，省电策略可能造成延迟。设备重启后需打开一次 App 恢复安排；应用更新以及时间、时区变化会重新安排。项目不申请精确闹钟、开机自启动或电池优化豁免权限。

## 系统展示与边界

应用对用户主动开始的持续行程请求标准 Android 实时更新。通过 `hasPromotableCharacteristics()` 和 `FLAG_PROMOTED_ONGOING` 查询实际状态，仅在系统已设置标记时显示“已提升”。权限、系统版本、通知渠道和省电策略会影响结果。

Android 通知由系统布局，封面、正文、按钮和小图标颜色以设备实际展示为准。标准请求与厂商专用服务卡片是不同能力；OPPO 专用服务卡片及小米场景模板需要相应授权和接入，不通过未确认参数宣称已开通。

“模拟导航课程并检查状态”可用于在当前设备检查通知展示，不打开地图。检查提醒、行程按钮、后台到达、关闭开关和超时恢复时，应使用明确指定的测试设备，并按脚本恢复数据。权限范围见 [权限说明](permissions.md)，保存与消息桥流程见 [架构说明](architecture.md)。

遇到提醒或行程未出现时，依次检查通知总开关及子项、系统通知权限/渠道、当前日期与课程周次、设备省电状态，再通过状态检查确认实际展示结果。历史设备记录不能替代当前版本的实机验证，设备脚本和环境要求见 [开发说明](development.md)。
